Implementation Notes — Phase 3

Achievement Engine · 2026-08-27 · Reveal Overlay + FAB + Trophy Case

Medal art is a Lucide icon, not a network image — resolves the spec's flagged risk

Context
Scout flagged that achievement.icon's real format was never settled in Phase 1 — the admin form labels it "Lucide icon name or asset ref," but the mockup's own medal art is always a wow.zamimg.com image URL, and the spec's preload step (Image().onload) only makes sense for a network image.
Decision
Committed to Lucide icon name as the actual convention (matching what the admin form's label already implied and what achievement-definitions.ts already seeds). MedalIcon resolves the name from a static ICON_MAP and renders the bundled component inside the coin/frame CSS treatment (color/filter substituted for the mockup's CSS filter on an <img>). Since every icon is already in the JS bundle, there is nothing to network-preload — the "preload every icon before playing" requirement is satisfied trivially (a single requestAnimationFrame gate, not an Image() race), documented in reveal-overlay.tsx's file header.
Alternative
Require real image URLs and build a proper preload path now (rejected — no real award artwork exists yet; building network-image handling for assets that don't exist would be pure speculation, and Lucide icons are exactly what the admin form already promises).

Dismiss simplified — no "fly medal to a shelf" animation

Context
The mockup's dismiss (flyHome) animates the medal flying to a persistent "Trophy Cabinet" shelf UI in the corner of the screen.
Decision
No such persistent shelf exists on the real dashboard, and building one wasn't in this phase's scope (the FAB is the only always-visible achievement affordance; the Trophy Case is a separate page, not a corner widget). Dismiss now just removes the overlay directly and calls onDismiss — a smaller departure from the mockup's ceremony, but the shelf's entire purpose (a satisfying "it landed somewhere") doesn't apply without a real landing target.
Alternative
Build a dashboard shelf widget solely to give the medal somewhere to fly to (rejected — out of scope, and would be new UI invented to serve an animation rather than a real need).

Blackout state — React state instead of direct class toggling

Context
The mockup toggles .blackout's on/off classes via direct DOM manipulation on a module-level element reference.
Decision
Since .ro-blackout is rendered by React (not appended imperatively like slashes/sparks), its on/off state is plain useState, toggled from the same cue-sheet callbacks. Every other beat (slashes, hitflash, spark canvas, class toggles on .ro-stage itself) stays imperative DOM manipulation via refs, matching the mockup — these are ephemeral, high-frequency FX elements where modeling every one as React state would be both slower and a needless rewrite of already-proven logic.
Alternative
Make blackout imperative too, for consistency (rejected — it's a single boolean toggle rendered once; React state is simpler here and there's no performance reason to avoid it, unlike the particle system).

profile.getMyProfile's "no user" fallback is missing primaryCharacterId

Context
The Trophy Case page resolves the caller's own family via getMyProfile. That procedure's "no user found" fallback branch returns a narrower character literal ({ name: "", characterId: -1, class: "" }) that's missing primaryCharacterId entirely — a real type inconsistency between its two return branches, caught by tsc when trophy-case.tsx tried to read the field.
Decision
Fixed defensively in trophy-case.tsx only, via a TypeScript in-check narrowing the union, rather than modifying profile.ts itself (a general-purpose router outside this phase's declared File Changes — widening the diff into it wasn't warranted for a one-call-site issue). Worth a follow-up to add primaryCharacterId: null to that fallback branch directly, so future consumers don't hit the same narrowing dance.
Alternative
Patch profile.ts's fallback branch now (rejected for this phase — out of declared scope, and the local fix is small and correct either way).

Trophy Case replay list — a separate per-award list alongside the summary display

Context
The spec's "Trophy Case surface with a per-award replay button" needs individual achievement_award row identity to replay a specific tier crossing, but achievement-display.tsx's getDisplayCatalog only returns achievement-level summaries (highest tier + progress), not individual award IDs.
Decision
Added a second component, ReplayList (inside trophy-case.tsx), backed by Phase 1's existing listAwardsForFamily procedure (already returns individual award rows with tier + achievement joined) — rendered below the summary display, each row with its own replay button that fetches getAwardById on demand and opens RevealOverlay for that single award.
Alternative
Add award-id-level detail to getDisplayCatalog's response instead (rejected — would conflate two different read-models with different shapes and different consumers; keeping them separate matches how the spec itself described two distinct query procedures).

Background dim/blur — reviewer-caught gap, fixed via backdrop-filter

Context
The mockup dims/blurs the dashboard behind the ceremony via a body.dimmed class applied to the live page DOM. The first pass of this port never carried that treatment over — only platinum's separate .ro-blackout covered the page, so bronze/silver/gold reveals played over a fully bright, undimmed background. Caught by review, cycle 1 (high finding).
Decision
Added a background + backdrop-filter: blur() brightness() saturate() directly on .ro-stage itself, applied for every tier. A portable overlay component can't reach into whatever page happens to be mounted behind it the way the mockup's own single-page body.dimmed class could — backdrop-filter achieves the same visual effect without requiring every host page to cooperate.
Alternative
Toggle a class on document.body from the component, mirroring the mockup exactly (rejected — couples this component to global body styling that would need to be defined once per host page rather than being self-contained).

achievement-queries.ts — added db as an injected first parameter

Context
The spec's Implementation Details declared all three functions as db-first, matching achievement-rules.ts's DI convention (Phase 2). A first pass imported db module-level instead, forcing tests into vi.mock("~/server/db"). Caught by review, cycle 1 (medium finding).
Decision
Added db: DB as the first parameter to getUnseenAwards/getDisplayCatalog/getAwardById, threaded through from ctx.db at each router call site. This also resolved the companion test-placement finding "for free": with DI, the query-logic tests no longer need module-mocking at all, so they moved into achievement.test.ts (calling the real functions through the router with a fake db object) exactly where the spec's own check command pointed — the separate achievement-queries.test.ts file was deleted.
Alternative
Keep the module-level import and duplicate coverage in both files (rejected — DI is strictly better here and was the spec's own stated pattern).

Visible achievements grouped by tier, and the glint overlay stays unported

Context
Two low findings from review, cycle 1: (1) achievement-display.tsx's visible list was flat, not grouped by tier like the replaced character-badges.tsx; (2) the mockup's decorative SVG "glint" catch-light on platinum's frame was never ported, undocumented.
Decision
(1) Fixed — AchievementDisplay now groups the visible list by highestTierEarned (platinum → gold → silver → bronze → not-yet-earned), matching the replaced component's pattern. (2) Left unported — purely decorative, no cue-sheet timing depends on it, and the medal is already a Lucide icon rather than a real image the glint was designed to catch light off of. Documenting the skip here, per the reviewer's own suggested resolution, rather than building it for a fidelity detail with no functional stakes.
Alternative
Port the SVG glint overlay for full visual fidelity (rejected — cosmetic-only cost against MedalIcon's flat Lucide rendering, not worth the added complexity for this pass).
